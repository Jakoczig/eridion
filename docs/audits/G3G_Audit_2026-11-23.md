## 2. Findings, most severe first

### F1 — High — Journal ranks lose to Inara and to expired Frontier (D0 violated; PR claim false)

`MergeJournalRanks` (`go/internal/history/source_priority.go:300-329`) only fills categories that are absent. When a category is already resolved, it keeps that source whatever its tier or eligibility. In real journals, Rank and Progress come before LoadGame, so journal ranks never reach commander provenance (commit `f7d2f8e` says this itself). They therefore always arrive through this merge, at the lowest effective priority.

- **Probe:** a temporary test, deleted afterwards. Inara Combat 5 plus live-journal Combat 3 resolved to `rank=5 source=inara`. Expired Frontier Combat 8 plus journal Combat 3 resolved to `rank=8 source=frontier stale=true`.
- **Failure scenario:** a commander refreshes Frontier once (Combat 8). Five minutes later the snapshot expires, and a later journal Rank event shows Combat 9. The Commander page keeps showing "Rank 8 · Frontier · not current". The same happens whenever Inara rank evidence exists: Inara beats the journal.
- PR #29's owner checklist says "after ~5 min without refresh, journal values return". For ranks that is false.
- **Why tests miss it:** `TestAuditMergeJournalRanks` only covers nil and fresh-Frontier inputs.
- **Fix:** treat live-reducer ranks as journal-tier candidates and re-run `ResolveEvidence` per category. Better, attribute pre-LoadGame Rank/Progress to the following LoadGame FID during normalization. Add Inara-vs-journal and expired-Frontier-vs-journal cases.

### F2 — High — On a commander switch, main-display connections stay open and requests carry no account epoch (Task 13 claim not true)

`switchAccount` (`webapp/devices.go:244-272`) closes only `m.connections`, which are the remote sockets. Owner sockets in `s.sockets` (`socket.go:69`) are closed only on shutdown (`server.go:200-208`). The `eridion-account-changed` event is a window-local DOM event fired only in the window that called `setGoAccounts` (`go-accounts.js:6`). No RPC envelope carries an account or connection epoch: `fieldops.go:76` checks `fid` only if the client sends one.

- **Failure scenario:** the main dashboard is open on A's Fleet page or itinerary, and the launcher switches to B. The dashboard socket stays open. Pages fetched under A stay on screen (Fleet until navigation, Commander up to 5 s). A queued `importGoItinerary` built from A's view runs against B's itinerary store.
- **Remote displays:** there is a narrower window. A request already read on the old socket can be dispatched after `SetAccounts` and execute under B, although its reply write fails.
- The ledger says "Open sockets are still closed on the switch, so no data or pending action from the previous commander survives". That is true only for paired displays.
- **Fix:** keep a server account epoch. Close every gameplay socket, owner sockets included, on a host switch. Stamp requests and replies with the epoch and reject mismatches. Extend `host_switch_test.go` with an owner socket and an in-flight mutating request.

### F3 — High — Exosuit equipment is not retained in durable history

`history/normalize.go:90` still excludes suit and loadout events from relevant-payload retention: the diff only splits Rank and Progress. Equipment exists only in the reducer cache (`paritystate/exosuit.go`). Task 14 asks to "retain bounded suit/loadout … event payloads", plus versioned enrichment of existing `{}` rows.

- **Failure scenario:** a cache-format bump (as `2839be7` already did), `rebuildGoHistory`, or a restore on a machine without the original journal files. Exosuit then shows unknown, even though history claims to hold the events.
- **Fix:** add the suit and loadout types to retention with bounded payloads. Then implement the planned source, offset and hash enrichment.

### F4 — Medium — A default that names an unknown commander is never recovered

`defaultRequiredLocked` (`gamestate/accounts.go:121-123`) only tests `Default == ""`. `LoadAccountSettings` copies a legacy `selected` into `Default` without checking it against verified commanders (`:64-66`).

- **Failure scenario:** a restored history from another profile, a legacy preference naming a commander whose history was removed, or eviction by the 64-commander cap (`service.go:577`). The display FID has no state, providers are pinned to it, and the launcher never asks for a choice.
- **Fix:** treat "default not in verified commanders" as `DefaultRequired`. Test that case and the "no known commander" case (plan Task 12, third bullet).

### F5 — Medium — "Launcher only" is enforced by role, not by launcher

`rpcAllowed` (`webapp/rpc_authority.go:51-56`) allows every launcher RPC for `role=="owner"`. The main gameplay display uses that same principal (`socket.go:29`). Settings are gone from the UI, but the main display can still call `configureGoProvider`, `setGoProviderCredential`, `stageGoRestore` and similar. Contract 4 is met visually, not by authority.

- **Fix:** give the launcher window its own principal or session scope, and test that a main-display socket gets `launcherOnlyError`.

### F6 — Medium-low — The default commander is adopted from the cache before catch-up

`adoptDefaultLocked` runs at cache restore (`service.go:271`), before new journals are replayed. That contradicts the comment at `:509` ("History is complete: adopt…").

- **Failure scenario:** the cache knows only A. While the app was closed, B was played. On start, A is silently persisted as default, so the one-time choice that the plan requires for ambiguity never happens.
- **Fix:** adopt only once the catch-up import completes.

### F7 — Medium — Equal-display tests check permissions, not equality

`TestAuditGameplayParity` and the rewritten G2F, G2G, G2MC and operations tests only assert the absence of an authorization error (`authorizationError`). The RPCs get `{}`, so a "Invalid request" reply passes. Task 13 asks for main/paired comparisons of identical data, source labels and action outcomes for the same FID. On the client side, the `assert.equal(owner, paired)` checks in `g2k-field.test.js` are good. The Go side has no equivalent.

- **Fix:** for each gameplay RPC with a valid fixture message, compare the normalized owner and viewer replies.

The regression `TestG2MCLegacyCacheRebuildNeverLooksComplete` uses a hook placed exactly in the gap and asserts the observed state; it adds no timing. No waits or retries were added.
